# Полный объём продукта

Владелец подтвердил: реализуем все функции поэтапно, небольшими осмысленными PR. Ниже — состояние исходного кода, а не end-to-end приёмка. Наличие клиентской интеграции не означает готовый серверный сценарий.

| Область | Что есть в коде | Что предстоит |
| --- | --- | --- |
| Аккаунты | Регистрация, вход, подтверждение и повторная отправка email, сброс пароля, выход | Правила, письма, одноразовые коды, ошибки, лимиты и защита от перебора |
| OAuth | Google/GitHub callbacks и BFF | Привязка идентичностей, конфликт email, безопасный callback |
| Сессии | me, refresh, список устройств и отзыв | Ротация, сроки жизни, изоляция пользователей, отзыв при смене пароля и блокировке |
| Профили | Публичный профиль, редактирование, аватар | Права, уникальность, ограничения, удаление аккаунта и данных |
| Посты/медиа | Несколько фото, crop/filters, локальный черновик, публикация, изменение/удаление | Проверка и хранение файлов, владение, порядок, очистка временных загрузок |
| Лента | Публичная лента, посты автора, viewer, курсоры | Видимость, персональная лента, заблокированные авторы и стабильная пагинация |
| Социальные действия | В моделях есть лайки и отношения; в PostViewerFooter кнопки лайка/сохранения и комментария без обработчиков | Лайки, комментарии, подписки на авторов, followers/following и их API |
| Поиск/избранное | SearchPage и FavoritesPage — заглушки | Объекты поиска и сохранения, сортировка, пагинация |
| Сообщения | MessengerPage — заглушка | Диалоги, права участников, история, доставка/прочтение; вложения уточнить |
| Уведомления | REST история/read-state, Socket.IO, polling | Типы событий, адресаты, доставка, дедупликация, переподключение |
| Перевод | Next.js вызывает провайдеров | Провайдер, лимиты, кеш, стоимость и ошибки |
| Платежи | История оплат; account-management использует SettingsStubPage | Тарифы, оформление/отмена, автопродление, webhook, повторные события, возвраты |
| Админка | GraphQL вход, список/поиск, бан/разбан/удаление пользователей | Роли, аудит, эффект блокировки и удаление данных |
| Разделы админки | Детали пользователя, posts/payments/statistics — placeholder | Детали и вкладки, модерация контента, оплаты и определения метрик |
| Статистика пользователя | StatisticsPage — заглушка | Метрики, права, периоды и источники данных |
| Локализация и документы | Шесть языков, terms/privacy | Локализация новых сценариев и актуальные продуктовые тексты |

Источники: `web/src/pages`, `web/src/features`, `web/src/widgets/post-viewer-modal/ui/components/PostViewerFooter.tsx`, `admin/src/app/[locale]`. Существующие интеграции: [API](api-inventory.md).

## Следующие небольшие PR

1. Архитектурное решение: расположение сервера, стек, границы модулей, протоколы web/admin.
2. Проектирование сессий, ролей и жизненного цикла аккаунта.
3. Модель данных пользователей, постов и медиа; миграции и хранение файлов.
4. Контракты и сценарии приёмки для auth, профилей и постов, затем остальных доменов.
5. Локальная инфраструктура и стратегия тестирования/эксплуатации.
6. Каркас сервера; отдельным PR — база и миграции; затем небольшие функциональные сценарии.

Это порядок обсуждения, а не утверждённый стек. Социальные действия требуют пользователей/постов; уведомления — определённых событий; сообщения — сессий и прав; платежи — согласованных тарифов и жизненного цикла подписки.

Один PR имеет одну цель, зависимости и проверяемый результат. Полный объём сохраняется; точные требования новых функций уточняются перед реализацией. Завершение фиксируется результатами проверок, документацией и состоянием доски.
