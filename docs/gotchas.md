# Грабли

Сюда попадают подтверждённые и воспроизведённые проблемы: условия, симптомы, причина, исправление и проверка. Предположения и риски до воспроизведения остаются в задачах, а не выдаются за доказанные ошибки.

## Web API без настроенного бэкенда

- **Условия:** запуск web без `API_URL` и запрос `GET /api/public-user`.
- **Результат:** HTTP 500; `bffFetch` сообщает, что `API_URL` не настроен. При этом страницы могут отвечать HTTP 200.
- **Что делать:** для работы с данными нужен совместимый сервер и настроенный адрес API. Успешный рендер страницы не подтверждает работу авторизации и данных.
- **Проверка:** воспроизведено при локальном запуске 2026-11-26; сквозной сценарий пока не проверен из-за отсутствия бэкенда.

## Админке нужен адрес API даже для сборки и запуска

- **Условия:** конфигурация GraphQL читает `NEXT_PUBLIC_API_URL` и выбрасывает ошибку при отсутствии значения.
- **Что делать:** при локальной проверке без сервера адрес можно задать в окружении процесса, например `NEXT_PUBLIC_API_URL=http://127.0.0.1:4000`; это заглушка адреса, а не работающий API.
- **Проверка:** с этим адресом dev-страница входа вернула HTTP 200, production-сборка прошла. Вход и GraphQL не проверялись.

## Предупреждения после обновления boundaries

- **Условия:** `eslint-plugin-boundaries` обновлён до версии 7, конфигурация использует прежний синтаксис правил.
- **Результат:** линтер выполняется, но предупреждает об устаревшем синтаксисе. Проверочный импорт из `shared` в `entities` был отклонён.
- **Что делать:** запланировать миграцию конфигурации с проверкой сохранения всех архитектурных ограничений; не отключать правила ради устранения предупреждений.
