# Архитектурные и продуктовые решения

Здесь фиксируются согласованные решения: контекст, выбранный вариант, причины, последствия и дата. Заменённые решения сохраняются с указанием нового решения.

## Открытые вопросы

- Детальная схема аккаунтов, сессии, роли и ID сущностей.
- Совместимость с REST и выбор API админки.
- Файловое хранилище, фоновые задания и окружения.
- Детальные продуктовые правила и необходимость переноса старых данных.

## 2026-11-26: полный продукт небольшими PR

Владелец подтвердил полный объём функций. Работа идёт последовательно: инвентаризация, проектирование, затем небольшие PR с одной целью и проверяемым результатом. Базовое архитектурное решение описано ниже.

## Отдельный модульный монолит и стек

Принято владельцем: `backend/` в текущем монорепозитории, NestJS + TypeScript, PostgreSQL + Drizzle. Причины: общие правила для двух клиентов, понятные границы модулей, SQL-транзакции и проверяемые миграции. Последствия: дополнительный процесс сервера, необходимость сопровождать SQL и явно проектировать межмодульные транзакции. Подробности — [целевая архитектура](backend-design.md).

## Общая версия выпуска и управляемые откаты

Принято владельцем: общая версия продукта, теги начиная с v0.1.0, changelog, отмена изменений через PR. Откат кода и восстановление данных — отдельные операции; миграции проектируются с периодом совместимости. Правила — [versioning.md](versioning.md). Первый релиз пока не назначен.
