# Состояние проекта

Обновлено: 2026-11-26.

В репозитории находятся пользовательское приложение `web`, админка `admin` и общие пакеты. Собственного бэкенда в репозитории нет. Пользовательское приложение обращается к внешнему REST API через Next.js BFF; админка использует GraphQL. Уведомления используют Socket.IO и резервный опрос.

Проведён первичный статический анализ структуры и основных интеграций. 26 ноября 2026 установлены зависимости через `npm ci` и проверен dev-запуск: главная web, страница входа web и страница входа admin ответили HTTP 200. Для admin временно задан локальный адрес API в процессе запуска. Без настроенного `API_URL` запрос web `/api/public-user` вернул HTTP 500. Вход, данные и сквозные сценарии без бэкенда не проверены. Некоторые экраны являются заглушками.

Исходный `npm ci` сообщил о 28 уязвимостях; Next.js остановил первый запуск с рекомендацией обновления. После обновления совместимых зависимостей и плагина архитектурных границ npm audit сообщил о нуле уязвимостей. Обе production-сборки, линтеры и stylelint прошли; web lint выводит 12 предупреждений, а плагин границ предупреждает об устаревшем формате конфигурации. Проверочный запрещённый импорт между слоями отклонён линтером. После обновления страницы входа web и admin ответили HTTP 200.

Следующий этап — совместно определить первую версию продукта и спроектировать свой бэкенд. Предложение об отдельном модульном монолите ещё не утверждено.

Подготовлена [инвентаризация функций](feature-inventory.md) и [существующих интеграций](api-inventory.md). Это статическая карта потребителей; полные серверные схемы и end-to-end сценарии ещё предстоит определить. Следующий шаг — решение об архитектуре и стеке, затем отдельные проектные PR.
